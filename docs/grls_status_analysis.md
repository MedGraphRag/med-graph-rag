# Статусы ГРЛС и целевая дозагрузка — 16 октября 2026

## Подтверждённые названия

Поле conditionValue официального API содержит:

- Д → Действующий.
- П → Действует, на подтверждении государственной регистрации.
- ИЗМ → Измененный.

Источник: https://rlp.minzdrav.gov.ru/medicine/portal/api/v0.1/medicament-registry . Публичный интерфейс https://rlp.minzdrav.gov.ru/registry/grls по умолчанию выбирает Д и П (проверено по его JavaScript).

Д и П можно использовать как явно помеченные реестром действующие состояния. П не следует путать с ПП («Приостановлено применение»). Наличие регистрации не является выводом о клинической применимости.

Для ИЗМ точное публичное описание жизненного цикла записи не найдено. Нельзя автоматически приравнять все ИЗМ к действующим либо отменённым регистрациям. Это статус изменённой записи; конкретные сведения и актуальную карточку нужно проверять отдельно. В сохранённой выборке одни номера РУ встречаются одновременно с ИЗМ и Д либо ИСКЛ. Предположение, что это связано с версиями регистрационных сведений, является интерпретацией данных, а не подтверждённым правилом API.

## Рекомендация

1. ИЗМ сохранять для распознавания названий с происхождением, не выдавая его за подтверждение действующей регистрации.
2. Не продолжать старую нефильтрованную загрузку с поздних страниц: в наблюдаемом диапазоне она даёт неполные объекты без торгового названия и АТХ.
3. Целевая загрузка Д/П с первой страницы полезна: новые связи подтверждены экспериментально. Ограничить первый запуск 100 страницами либо остановкой unusable_page; не объявлять его полным. Ранее проверенная страница 101 при size=100 даже с этими фильтрами была непригодна.
4. Для дальнейшего покрытия отдельно исследовать ЕАЭС и другие статусы. Известный дефект API не позволяет гарантировать, что все оставшиеся записи бесполезны или что 100 страниц дают всю полезную выборку.
5. Объединять новые и прежние связи с дедупликацией, сохраняя статус и lpId в таблице происхождения. В ETL добавлен повторяющийся --additional-input-dir для объединения snapshot с сохранением источника, страницы и статуса каждой записи.

## Выполненная целевая загрузка

Позднее 16.10.2026 по запросу пользователя скачаны 100 страниц с Д/П, snapshot_20261016T130852032029Z. Получено 10000 уникальных записей: 9933 Д и 67 П, у 9454 заполнен atx. Загрузка без ошибок остановлена по max_pages_reached; регистр целиком не выгружен.

После объединения с первоначальной выборкой основной grls_normalized.parquet содержит 8369 связей (+3883). Все прежние 4486 связей сохранены, пустых связей нет. SHA-256 исходных JSON до и после ETL совпадают. Происхождение содержит по 10000 наблюдений из каждого snapshot. Прежний результат находится в backups/grls-before-active-merge-20261016T131040524080Z.
