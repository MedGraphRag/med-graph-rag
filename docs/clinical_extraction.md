# Извлечение клинических утверждений

Поддерживаются пробный запуск по одной странице и последовательная обработка
всех подготовленных страниц из Parquet. Записи в граф пока нет.

## Пробный запуск на настоящих КР

По умолчанию используется локальная Ollama с моделью `gemma4:12b` через
совместимый с OpenAI API. Установите Ollama и загрузите модель:

```bash
ollama pull gemma4:12b
ollama run gemma4:12b
```

`ollama run` позволяет проверить модель вручную; выйти из чата можно через `/bye`.
Для работы Python нужен запущенный сервер Ollama (обычно запускается приложением;
при необходимости запустите `ollama serve` в отдельном терминале).
В существующем `.env` замените старые настройки LLM:

```dotenv
LLM_BASE_URL="http://localhost:11434/v1"
LLM_API_KEY="ollama"
LLM_MODEL="gemma4:12b"
LLM_TIMEOUT=300
```

Ключ для локальной Ollama не нужен: `ollama` — служебное значение для SDK.
Без переменных LLM используются эти же значения по умолчанию. Старые значения
в `.env` имеют приоритет, поэтому их нужно обновить. Настройки Neo4j для извлечения
не требуются. Если Ollama работает на другом хосте, укажите его в `LLM_BASE_URL`.
`LLM_TIMEOUT` задаёт таймаут SDK в секундах; для медленного локального запуска
его можно увеличить. Схемы утверждений, промпт и проверки цитат сохранены.

Если модель долго отвечает, можно сравнить извлечение с отключёнными
рассуждениями через совместимый API Ollama:

```bash
LLM_REASONING_EFFORT=none python -m src.nlp.clinical_evaluation
```

Переменная передаётся в API как `reasoning_effort`. Для постоянной настройки
добавьте `LLM_REASONING_EFFORT="none"` в `.env`. При отсутствии или пустом значении
используются настройки рассуждений сервера. Допустимые значения и возможность
отключения зависят от модели и API. Качество извлечения при смене режима нужно
сравнить на эталоне. Эта настройка действует также в пробном запуске и батче.
Выбранное значение сохраняется в отчётах оценки и пробного извлечения, а также
в `manifest.json` батча. При смене режима продолжение незавершённого батча требует
нового каталога результатов.

Из корня проекта запустите:

```bash
python -m src.nlp.clinical_trial
```

Команда выбирает одну страницу из `data/processed/cr_pages.parquet` со словами
о противопоказаниях или взаимодействиях. Текст передаётся модели целиком.
Это небольшая выборка для проверки работы, а не полная обработка десяти КР.

Для быстрой пробы на странице с минимумом текста:

```bash
LLM_REASONING_EFFORT=none python -m src.nlp.clinical_trial --shortest
```

`--shortest` выбирает самую короткую непустую страницу без поиска по ключевым
словам; его можно сочетать с `--document`, но нельзя с `--page`. В терминале
выводится длина выбранного текста. На такой странице связей может не быть:
пустой список проверяет выполнение запроса, но не качество извлечения связей.

Для `inclusionai/ling-3.2-flash:free` пробный запуск отключает внутренние
рассуждения через `reasoning.enabled=false`. Скрипт выводит сообщения перед
запросом и после получения структурированного ответа.

Для выбранного документа можно указать `--document <CodeVersion>`, а для точного
выбора страницы также `--page <номер>`. Тогда поиск по ключевым словам не нужен.
Идентификатор берётся из `code_version`: он соответствует версии документа,
а не внутреннему числовому `document_id` в исходной таблице страниц.

Результат сохраняется в новый JSON в `data/processed/clinical_trials/`.
В терминале выводятся время извлечения связей и отдельно время сопоставления
с ГРЛС в секундах; они сохраняются в JSON в `timings_seconds`.
Время извлечения включает ожидание ответа, повторы Instructor и автоматические
проверки утверждений. Загрузка Parquet и справочника в этот замер не входит.
При ошибке запроса затраченное на извлечение время также выводится в терминал.
Папка исключена из Git. Другой новый файл можно задать через `--output`.
Существующие файлы не перезаписываются. Если запрос завершился ошибкой,
она не подменяется пустым результатом.

В JSON есть полный исходный фрагмент, извлечённые утверждения, точные цитаты,
отрицания, условия и варианты поиска названий в ГРЛС. Ключи API не сохраняются.
Поле `manual_review` изначально равно `not_requested`.
Массовая обработка не требует одобрения человеком каждого утверждения.
Для оценки качества вручную проверяется небольшая эталонная выборка.

Для проверки нужно сравнить цитату со страницей PDF, оценить участников,
смысл отрицания и полноту условий. Если на странице нет связей нужного типа,
пустой результат допустим и не означает отсутствие таких связей во всём документе.

## Батч по подготовленным страницам

Вход — существующий `data/processed/cr_pages.parquet` с колонками
`code_version` (строка), `page_number` (целое от 1) и `text` (строка или null).
Необязательная `section_title` добавляется к расположению источника.
Другие колонки допускаются. Дубликаты пары документ/страница и некорректные
метаданные останавливают запуск до запросов к модели.

```bash
# Проверка выборки: без LLM, справочника ГРЛС и записи файлов
python -m src.nlp.clinical_batch --dry-run

# Небольшой первый запуск
python -m src.nlp.clinical_batch --limit 5 --output-dir data/processed/clinical_batches/first

# Все страницы всех подготовленных документов
python -m src.nlp.clinical_batch --output-dir data/processed/clinical_batches/full

# Один документ; --document можно повторять
python -m src.nlp.clinical_batch --document 28_3

# Продолжить после Ctrl+C или остановки процесса
python -m src.nlp.clinical_batch --output-dir data/processed/clinical_batches/full --resume

# Дополнительно повторить ранее ошибочные страницы
python -m src.nlp.clinical_batch --output-dir data/processed/clinical_batches/full --resume --retry-errors
```

Страницы сортируются по `code_version`, затем по номеру. `--limit` ограничивает
эту выборку, включая пустые страницы. При продолжении нужно повторить исходные
`--document`, `--limit`, `--pages` и `--dictionary`, если они были заданы.
По умолчанию пути совпадают с пробным запуском одной страницы.
Без `--output-dir` создаётся новый каталог с отметкой времени UTC.
Для обычного запуска каталог должен отсутствовать; существующий используется
только с `--resume`. Не запускайте два процесса с одним каталогом результата.

Батч передаёт каждую непустую страницу целиком, без поиска по ключевым словам,
сокращения текста и разбиения на части. Страницы из одних пробелов и null
фиксируются как `skipped_empty`, без вызова модели. Ошибки API, формата ответа
или сопоставления фиксируются как `error`; следующие страницы обрабатываются.
Повторы неверного ответа выполняет существующий Instructor. Пустой успешный
ответ `relations: []` отличается от ошибки. Новых автоматических повторов
целой страницы в батче нет; повтор ошибок запускается явно.

В каталоге результата:

| Файл | Содержимое |
|---|---|
| `manifest.json` | Модель, версия формата, время начала и SHA-256 входной выборки, справочника и кода обработки |
| `pages/<hash>_<page>.json` | Полная исходная страница, статус обработки; при успехе — фрагмент и утверждения с результатами поиска ГРЛС; при ошибке — тип исключения |
| `summary.json` | Число успешных, пустых, ошибочных и ожидающих страниц, число утверждений, распределение статусов и признак Ctrl+C |

Файлы публикуются атомарной заменой после завершения записи. Контрольная точка
создаётся после каждой страницы, сводка восстанавливается по этим файлам при
продолжении. Прерванная страница без готового файла будет запрошена повторно.
Повреждённая контрольная точка останавливает продолжение и не затирается.
Изменение выбранного текста, состава выборки, справочника, кода или модели
требует нового каталога. При завершённом батче `--resume` не открывает клиент LLM.
Параметры сервера и ключи API не сохраняются; текст исключений SDK также не
записывается, поскольку может содержать секреты или ответ сервера.

Коды завершения: `0` — все выбранные страницы обработаны или пусты;
`1` — есть ошибки страниц либо запуска; `130` — прерывание через Ctrl+C.
При ошибке записи запуск останавливается: несохранённая страница остаётся
ожидающей. Результаты исключены из Git. Автоматические проверки, отрицания,
условия и сопоставление ГРЛС такие же, как при извлечении одной страницы.
Связи между разными страницами этим способом не извлекаются; полнота и
медицинская корректность требуют отдельной оценки. Записи в Neo4j нет.

## Использование из Python

Пример из корня проекта с настройками из локального `.env`:

```python
from src.nlp.clinical_extractor import extract_relations
from src.nlp.clinical_llm import extraction_client
from src.nlp.clinical_relations import ClinicalFragment

# Пример вымышленный. Для работы подставьте подготовленный фрагмент КР.
fragment = ClinicalFragment(
    document_id="synthetic-example",
    location="Страница 2, учебный раздел",
    page_number=2,
    text="Препарат А не противопоказан при заболевании Б при условии В.",
)

with extraction_client() as (client, model):
    result = extract_relations(
        fragment, client=client, model=model,
    )

print(result.model_dump_json(indent=2))
```

Используется температура 0. Ошибки формата ответа приводят к повтору запроса через
Instructor; после исчерпания повторов ошибка передаётся вызывающему коду.
Пустой список связей не подменяет ошибку API.

Документ, страница и расположение берутся из входного фрагмента.
Цитата сначала ищется дословно. Если точного совпадения нет, допускаются
только различия в пробелах и переносах строк. При однозначном совпадении
сохраняется дословный фрагмент исходного текста с его пробелами и переносами.
Слова, числа, регистр и пунктуация при поиске цитаты не исправляются.
При проверке условий также допускаются только различия в пробельных символах.
Если цитаты нет, её расположение неоднозначно, метаданные не совпадают,
участники или указанные условия не находятся в цитате либо утверждение содержит
сомнение (`uncertain`), связь получает статус `disputed`.
Остальные связи получают `unresolved`: названия ещё не
сопоставлены со справочниками. Отрицание сохраняется в `polarity`.

Эти проверки не подтверждают медицинский смысл и полноту условий.
Сопоставление названий и оценка качества на эталоне выполняются отдельно.
Ручная проверка выбранных записей доступна как дополнительная возможность.
ГРЛС не используется как источник клинических утверждений.

## Сопоставление лекарств с ГРЛС

После извлечения можно сопоставить лекарства с существующим Parquet-справочником:

```python
from src.nlp.clinical_resolver import resolve_relation_drugs
from src.nlp.grls_resolver import DrugResolver

resolver = DrugResolver("data/processed/grls_normalized.parquet")
resolved = [resolve_relation_drugs(relation, resolver) for relation in result.relations]

for item in resolved:
    print(item.model_dump_json(indent=2))
```

Для каждого лекарства сохраняются исходное название и все варианты поиска.
МНН и список АТХ заполняются только при однозначном результате.
Используется признак неоднозначности существующего поиска, без выбора первого
варианта и без нечёткого сопоставления. Составное МНН сохраняется целиком.

Если лекарство не найдено, неоднозначно или у него нет МНН, утверждение остаётся
`unresolved`. Если все лекарства сопоставлены, статус меняется на `auto_checked`.
Сопоставление не снимает статусы `disputed` и `rejected` и не меняет исходное
утверждение, отрицание, условия или источник. Статус `confirmed` недоступен.

Заболевания этим шагом не сопоставляются с МКБ-10. Даже при статусе
`auto_checked` нельзя считать автоматические проверки медицинским подтверждением.
Совпадения МНН/АТХ не создают новых противопоказаний или взаимодействий.

## Тесты

Для оценки ответов настоящей модели на размеченных утверждениях:

```bash
python -m src.nlp.clinical_evaluation
python -m src.nlp.clinical_evaluation --min-accuracy 0.8
```

Описание метрик и ограничений — в [clinical_reference.md](clinical_reference.md).
Команда обращается к LLM; PDF, Parquet и Neo4j для этой оценки не требуются.

Выборка из настоящих КР, её ограничения и проверки без модели описаны
в [clinical_reference.md](clinical_reference.md).

Тесты не обращаются к LLM: HTTP-ответы подменяются, а Instructor и Pydantic
обрабатывают их как обычные ответы сервера.

```bash
python -m pytest -q tests/test_clinical_relations.py tests/test_clinical_extractor.py tests/test_clinical_resolver.py tests/test_grls_resolver.py
python -m pytest -q tests/test_clinical_trial.py
python -m pytest -q tests/test_clinical_batch.py
python -m pytest -q tests/test_clinical_reference.py
python -m pytest -q tests/test_clinical_llm.py tests/test_clinical_evaluation.py
```
