# Извлечение клинических утверждений

Поддерживаются пробный запуск по одной странице и последовательная обработка
всех подготовленных страниц из Parquet. Записи в граф пока нет.

## Пробный запуск на настоящих КР

В локальном `.env` должны быть заполнены `LLM_API_KEY`, `LLM_BASE_URL` и `LLM_MODEL`.
Из корня проекта запустите:

```bash
python -m src.nlp.clinical_trial
```

Команда выбирает одну страницу из `data/processed/cr_pages.parquet` со словами
о противопоказаниях или взаимодействиях. Текст передаётся модели целиком.
Это небольшая выборка для проверки работы, а не полная обработка десяти КР.

Для `inclusionai/ling-3.2-flash:free` пробный запуск отключает внутренние
рассуждения через `reasoning.enabled=false`. Скрипт выводит сообщения перед
запросом и после получения структурированного ответа.

Для выбранного документа можно указать `--document <CodeVersion>`, а для точного
выбора страницы также `--page <номер>`. Тогда поиск по ключевым словам не нужен.
Идентификатор берётся из `code_version`: он соответствует версии документа,
а не внутреннему числовому `document_id` в исходной таблице страниц.

Результат сохраняется в новый JSON в `data/processed/clinical_trials/`.
Папка исключена из Git. Другой новый файл можно задать через `--output`.
Существующие файлы не перезаписываются. Если запрос завершился ошибкой,
она не подменяется пустым результатом.

В JSON есть полный исходный фрагмент, извлечённые утверждения, точные цитаты,
отрицания, условия и варианты поиска названий в ГРЛС. Ключи API не сохраняются.
Поле `manual_review` изначально равно `not_requested`.
Массовая обработка не требует одобрения человеком каждого утверждения.
Для оценки качества вручную проверяется небольшая эталонная выборка.

Для проверки нужно сравнить цитату со страницей PDF, оценить участников,
смысл отрицания и полноту условий. Если на странице нет связей нужного типа,
пустой результат допустим и не означает отсутствие таких связей во всём документе.

## Использование из Python

Пример из корня проекта с настройками из локального `.env`:

```python
import os

import instructor
from dotenv import load_dotenv
from openai import OpenAI

from src.nlp.clinical_extractor import extract_relations
from src.nlp.clinical_relations import ClinicalFragment

load_dotenv()

# Пример вымышленный. Для работы подставьте подготовленный фрагмент КР.
fragment = ClinicalFragment(
    document_id="synthetic-example",
    location="Страница 2, учебный раздел",
    page_number=2,
    text="Препарат А не противопоказан при заболевании Б при условии В.",
)

with OpenAI(
    api_key=os.environ["LLM_API_KEY"],
    base_url=os.environ["LLM_BASE_URL"],
    timeout=60,
    max_retries=0,
) as openai_client:
    client = instructor.from_openai(openai_client, mode=instructor.Mode.JSON)
    result = extract_relations(
        fragment, client=client, model=os.environ["LLM_MODEL"],
    )

print(result.model_dump_json(indent=2))
```

Используется температура 0. Ошибки формата ответа приводят к повтору запроса через
Instructor; после исчерпания повторов ошибка передаётся вызывающему коду.
Пустой список связей не подменяет ошибку API.

Документ, страница и расположение берутся из входного фрагмента.
Цитата сначала ищется дословно. Если точного совпадения нет, допускаются
только различия в пробелах и переносах строк. При однозначном совпадении
сохраняется дословный фрагмент исходного текста с его пробелами и переносами.
Слова, числа, регистр и пунктуация при поиске цитаты не исправляются.
При проверке условий также допускаются только различия в пробельных символах.
Если цитаты нет, её расположение неоднозначно, метаданные не совпадают,
участники или указанные условия не находятся в цитате либо утверждение содержит
сомнение (`uncertain`), связь получает статус `disputed`.
Остальные связи получают `unresolved`: названия ещё не
сопоставлены со справочниками. Отрицание сохраняется в `polarity`.

Эти проверки не подтверждают медицинский смысл и полноту условий.
Сопоставление названий и оценка качества на эталоне выполняются отдельно.
Ручная проверка выбранных записей доступна как дополнительная возможность.
ГРЛС не используется как источник клинических утверждений.

## Сопоставление лекарств с ГРЛС

После извлечения можно сопоставить лекарства с существующим Parquet-справочником:

```python
from src.nlp.clinical_resolver import resolve_relation_drugs
from src.nlp.grls_resolver import DrugResolver

resolver = DrugResolver("data/processed/grls_normalized.parquet")
resolved = [resolve_relation_drugs(relation, resolver) for relation in result.relations]

for item in resolved:
    print(item.model_dump_json(indent=2))
```

Для каждого лекарства сохраняются исходное название и все варианты поиска.
МНН и список АТХ заполняются только при однозначном результате.
Используется признак неоднозначности существующего поиска, без выбора первого
варианта и без нечёткого сопоставления. Составное МНН сохраняется целиком.

Если лекарство не найдено, неоднозначно или у него нет МНН, утверждение остаётся
`unresolved`. Если все лекарства сопоставлены, статус меняется на `auto_checked`.
Сопоставление не снимает статусы `disputed` и `rejected` и не меняет исходное
утверждение, отрицание, условия или источник. Статус `confirmed` недоступен.

Заболевания этим шагом не сопоставляются с МКБ-10. Даже при статусе
`auto_checked` нельзя считать автоматические проверки медицинским подтверждением.
Совпадения МНН/АТХ не создают новых противопоказаний или взаимодействий.

## Тесты

Выборка из настоящих КР, её ограничения и проверки без модели описаны
в [clinical_reference.md](clinical_reference.md).

Тесты не обращаются к LLM: HTTP-ответы подменяются, а Instructor и Pydantic
обрабатывают их как обычные ответы сервера.

```bash
python -m pytest -q tests/test_clinical_relations.py tests/test_clinical_extractor.py tests/test_clinical_resolver.py tests/test_grls_resolver.py
python -m pytest -q tests/test_clinical_trial.py
python -m pytest -q tests/test_clinical_reference.py
```
