# Проверка назначений

Чекер проверяет пары «лекарство — заболевание» и «лекарство — лекарство».
Результат содержит статус, найденные варианты лекарств, подтверждённые связи,
условия применимости и источники с дословной цитатой и её расположением.

## Запуск

Нужны заполненные `NEO4J_URI`, `NEO4J_USER`, `NEO4J_PASSWORD` в локальном
`.env`, импортированный лекарственный граф и клинические связи из этапа извлечения.
Названия разрешаются через существующий `grls_normalized.parquet`.

```bash
python -m src.graph.prescription_cli drug-disease --drug "название препарата" --icd10 "код МКБ-10"
python -m src.graph.prescription_cli drug-drug --first "первый препарат" --second "второй препарат"
```

Другой справочник и базу можно выбрать аргументами `--dictionary` и `--database`
перед подкомандой. `--help` работает без локального `.env`.

Статусы результата:

- `confirmed_match` — найдены подтверждённые связи для определённой пары.
- `ambiguous` — название соответствует нескольким вариантам, варианты возвращены для уточнения.
- `insufficient_data` — нет подходящих связей или недостаточно входных данных.

Условия применимости возвращаются текстом для оценки конкретного случая.
Отсутствие связи не является доказательством безопасности.
Ошибки подключения, схемы и валидации приводят к ненулевому коду выхода.
Код выхода 0 означает, что проверка выполнена, включая результаты
`ambiguous` и `insufficient_data`.

## Формат клинических связей

Используются узлы импорта ГРЛС из PR #32
`INN {key: 'name:<полное нормализованное МНН>', name_norm: '<МНН>'}`
и существующие узлы `ICD10 {code}`.

```text
(INN)-[:CONTRAINDICATED_FOR]->(ICD10)
(INN)-[:INTERACTS_WITH]->(INN)
```

Типы клинических связей задаются этим чекером как контракт для этапа извлечения.
На каждой связи обязательны свойства:

| Свойство | Содержимое |
|---|---|
| status | Только confirmed допускается в результат проверки |
| document_id | Идентификатор документа клинических рекомендаций |
| location | Страница, раздел или другой точный локатор цитаты |
| quote | Непустая дословная цитата |
| conditions | Список условий, явно пустой список для безусловной связи |
| description | Непустое описание взаимодействия, обязательно для INTERACTS_WITH |

Для нескольких источников сохраняются отдельные связи со своими цитатами
и условиями. Порядок участников `INTERACTS_WITH` хранит роли исходного утверждения.
Поиск работает при любом порядке ввода препаратов.

Состояние `confirmed` выставляет этап проверки извлечённых утверждений.
Он должен проверить цитату, разрешить названия, сохранить ограничения и допускать
в `CONTRAINDICATED_FOR` только утверждения о наличии противопоказания.
Спорные, отрицаемые и неразрешённые утверждения не публикуются как подтверждённые.
Чекер не повышает статус записи самостоятельно.

ГРЛС используется для идентификации препаратов. Клинические утверждения
поступают из клинических рекомендаций. Совпадение АТХ и иерархия МКБ-10
не порождают дополнительные клинические связи. Составные МНН сопоставляются целиком.

## Использование из Python

`Neo4jPrescriptionChecker(driver, resolver, database=None)` находится в
`src.graph.prescription_graph`. Он принимает существующий Neo4j Driver и
объект поиска с методом `search(query) -> DrugSearchResult`.
Подходят `DrugResolver` для Parquet и `GRLSGraphResolver` из PR #32.
Методы `check_drug_disease` и `check_drug_drug` принимают названия лекарств.

## Проверки

```bash
python -m pytest -q tests/test_prescription_checker.py tests/test_prescription_graph.py tests/test_grls_resolver.py
```

Тесты проверяют обработку статусов, источников, условий, неоднозначности, ошибки
базы и командный путь от названий до JSON. Ответы Neo4j в них подменены.
Интеграционная проверка на реальном графе требует сервера Neo4j и извлечённых связей.

Для интеграционного теста с настроенным Neo4j:

```bash
RUN_PRESCRIPTION_NEO4J_TESTS=1 python -m pytest -q tests/test_prescription_neo4j.py
```

Тест создаёт синтетические узлы с уникальными идентификаторами и удаляет их
в конце запуска. По умолчанию он пропускается.
