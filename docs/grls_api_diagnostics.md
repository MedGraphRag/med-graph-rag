# Диагностика API ГРЛС — 16 октября 2026

Проверка проведена по сохранённым raw-страницам и ограниченным публичным HTTPS-запросам с проверкой TLS. Cookies, токены и авторизация браузера не использовались. Повторная полная выгрузка не выполнялась.

## Фильтры интерфейса и API

В публичном JavaScript страницы https://rlp.minzdrav.gov.ru/registry/grls обнаружена инициализация `conditionIds: ["Д", "П"]`. Интерфейс получает количество записей из HTTP-заголовка `x-total-count`. Подкомпонент API вызывается по пути `/medicine/portal/api/v0.1/medicament-registry`.

Ограниченные диагностические запросы:

| Параметры | Объектов | С lpId / торговым названием | x-total-count |
|---|---:|---:|---:|
| page=1, size=100, без фильтра | 100 | 100 / 100 | 133122 |
| page=1, size=100, conditionIds=Д&conditionIds=П | 100 | 100 / 100 | 16585 |
| page=101, size=100, conditionIds=Д&conditionIds=П | 100 | 0 / 0 | 16585 |
| page=166, size=100, conditionIds=Д&conditionIds=П | 85 | 0 / 0 | 16585 |
| page=167, size=100, conditionIds=Д&conditionIds=П | 85 | 0 / 0 | 16685 |
| page=667, size=15, conditionIds=Д&conditionIds=П | 15 | 0 / 0 | 16585 |
| page=668, size=15, conditionIds=Д&conditionIds=П | 15 | 0 / 0 | 16585 |

Следовательно, 16585 относится к отфильтрованной выборке интерфейса. Но фильтр не устраняет деградацию ответов, а счётчик нельзя использовать как доказательство полноты: за заявленным концом API отдаёт объекты и меняет итог. Точная причина внутри сервера по этим наблюдениям не установлена. Предположение об ограничении обогащения/соединения данных около 10000 записей требует подтверждения владельцем API; считать его документированным лимитом нельзя.

## Сохранённая выгрузка

`snapshot_20261016T105630721477Z` остановлен после 1193 страниц (119300 объектов):

- Страницы 1–100: 10000 уникальных непустых lpId; 6837 уникальных регистрационных номеров; 9225 объектов с АТХ. Большинство объектов имеет состояние «Измененный» — это не выборка только действующих препаратов.
- Страницы 101–1193: 109300 объектов без lpId, торгового названия, статуса и АТХ. При этом могут присутствовать МНН, регистрационный номер, владелец, regdata.regId и medFormsName.
- В этой второй группе 32228 уникальных регистрационных номеров и 109300 уникальных regdata.regId. Хеши полных объектов различаются, поэтому прежняя защита от повторов не останавливала загрузку.
- В старом manifest после прерывания `termination_reason=null`: CancelledError не обрабатывался. Этот файл сохранён как есть, его статистика не является подтверждением полноты.

Сырые страницы и существующие Parquet во время диагностики не изменялись.

## Исправления загрузчика и ETL

- Непустая страница, на которой у всех объектов одновременно отсутствуют lpId и непустое commercialName, сохраняется в raw и останавливает загрузку как `unusable_page`.
- Manifest хранит `quality_issue`, начальный `api_total_count_initial` и счётчик API для каждого ответа в `response_encodings`. Значения считаются наблюдениями, а не гарантией полноты.
- Manifest записывается атомарно при старте и после каждой обработанной страницы. Ctrl+C помечается как `interrupted`.
- ETL по умолчанию блокирует такие страницы до записи выходных файлов, в том числе с `--allow-incomplete`. Для принятого пользователем частичного справочника добавлен отдельный `--mapped-only`: он пропускает в поисковую таблицу только заполненные связи торговое название → МНН → АТХ, сохраняет исходные JSON и пишет отчёт исключений. Страницы без единой заполненной исходной связи пропускаются целиком, их список и количество объектов записываются в отчёт. На смешанных страницах пригодные записи сохраняются. Полнота при этом не подтверждается.

Фильтр по умолчанию не добавлен. Для явного сравнения с выборкой интерфейса нужны повторяющиеся `--condition-id Д --condition-id П`, однако повторять полную загрузку пока не следует: фильтр не исправляет серверные ответы.

## Что остаётся проверить

Проверить официальный экспорт CSV/XLSX из интерфейса (его схемы и полноту), возможность документированного разбиения выборки либо получить разъяснение оператора API. Не восстанавливать торговые названия по одному номеру РУ без проверки версии/связей. Первые 100 страниц можно считать лишь частичным источником для диагностики; они не заменяют полный справочник.

## Обход ограничения для выборки Д/П

Код интерфейса лекарственных препаратов использует фильтры `entryDateStart` и `entryDateEnd` (ISO datetime), а не `entry-start`/`entry-end`, которые относятся к другому компоненту. Неподдерживаемые параметры API может молча игнорировать; их нельзя считать рабочим разбиением.

Добавлен `src/nlp/grls_active.py`: контрольный запрос общего количества Д/П до и после, последовательная выгрузка частей с границами 2024-01-01 и 2025-01-01, проверка идентификаторов и статусов. Измеренные размеры частей: 6013 + 4027 + 6545 = 16585. Сборщик публикует итоговый snapshot только после сверки уникальных lpId и общего счётчика, без потери записей без АТХ. Каждое тело ответа копируется в него без изменений, с проверкой SHA-256 и указанием исходной страницы/фильтров в manifest.

Полнота относится только к указанной выборке Д/П на момент запроса. Другие состояния реестра не включены. При изменении числа записей во время выгрузки, неполной части или повторяющихся идентификаторах, мешающих сверке покрытия, сборка не считается успешной.
