# GRLS --- raw archive

## Получение данных

1. Скачать актуальный ZIP-архив с официального сайта ГРЛС:  
   https://grls.minzdrav.gov.ru/grls.aspx
2. Распаковать архив.
3. Поместить полученные `.xlsx` файлы в `data/raw/grls/`.

## Проверка

После размещения файлов в `data/raw/grls/` выполнить:

```bash
python -c "import pandas as pd; from pathlib import Path; files=sorted(Path('.').glob('*.xlsx')); assert len(files)==8, f'Ожидалось 8 XLSX, найдено {len(files)}'; required={'Торговое наименование\nлекарственного препарата','Международное непатентованное или химическое наименование'}; [(lambda cols: (_ for _ in ()).throw(AssertionError(f'{f.name}: отсутствуют {required-set(cols)}')) if not required.issubset(cols) else print(f'OK: {f.name}'))(set(map(str, pd.read_excel(f, header=4, nrows=0).columns))) for f in files]; print(f'\nПРОВЕРКА ПРОЙДЕНА: {len(files)} XLSX-файлов')"
```

Проверка подтверждает наличие 8 исходных XLSX-файлов и обязательных полей торгового наименования и МНН.

## Состав архива

В архиве находятся 8 исходных XLSX-файлов, разделённых по статусу регистрационных удостоверений:

- `grls2026-10-06-1-Действующий.xlsx`
- `grls2026-10-06-1-Изменённый.xlsx`
- `grls2026-10-06-1-Исключённый.xlsx`
- `grls2026-10-06-1-Истёкший.xlsx`
- `grls2026-10-06-1-Выдано_по_правилам_ЕАЭС.xlsx`
- `grls2026-10-06-1-Действует_на_подтверждении_государственной_регистрации.xlsx`
- `grls2026-10-06-1-Приостановлено_применение.xlsx`
- `grls2026-10-06-1-Действует_в_иностранных_упаковках.xlsx`

## Структура XLSX

Исходные XLSX содержат технические и рабочие поля. Для проекта представляют интерес:

- Номер регистрационного удостоверения
- Дата регистрации
- Дата окончания действия регистрационного удостоверения
- Торговое наименование лекарственного препарата
- Международное непатентованное или химическое наименование
- Формы выпуска
- Фармако-терапевтическая группа

Отдельного поля **ATC / АТХ-код** в исходной выгрузке нет.

## Важные замечания

- Raw-файлы сохраняются без нормализации и удаления дубликатов.
- Некоторые поля исходной выгрузки могут быть пустыми.
- Преобразования исходных данных выполняются только на следующем этапе ETL.
