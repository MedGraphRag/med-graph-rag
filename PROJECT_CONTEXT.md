# MedGraphRAG: контекст проекта

## Назначение

Информационно-поисковая GraphRAG-система по клиническим рекомендациям Минздрава РФ. Связывает лекарства с МНН и АТХ и использует граф для проверки противопоказаний и межлекарственных взаимодействий.

Ответы должны опираться на документы и связи графа с указанием источников. Генерация клинических рекомендаций из памяти модели запрещена; температура генерации — 0. Система не хранит персональные данные пациентов.

## Архитектура

```text
Официальные источники → raw → валидация и ETL → справочники и извлечённые связи
                                              ↓
                                     Neo4j → LangGraph → Streamlit
```

- Python 3.11+, httpx для асинхронного HTTP, Polars для таблиц, Pydantic v2 для структурированных сущностей.
- Целевой стек: Instructor, Sentence-Transformers, Neo4j 5.x с APOC/GDS, LangGraph, Streamlit, Ragas и Owlready2. Инференс — через совместимый с OpenAI SDK интерфейс с локальной конфигурацией.
- Сбор и ETL ГРЛС реализованы в `src/nlp/`. Граф, агенты и интерфейс развиваются отдельными модулями; наличие компонента в целевой архитектуре не означает его готовность.
- Не добавлять pandas, собственные C/C++-вставки, FFI или новые технологии без необходимости.

## ГРЛС

Источник — публичный API `https://rlp.minzdrav.gov.ru/medicine/portal/api/v0.1/medicament-registry`.

| Модуль | Назначение |
|---|---|
| `src/nlp/grls_scraper.py` | Последовательные страницы с 1, размер до 100, фильтры, паузы, retry и manifest |
| `src/nlp/grls_active.py` | Сбор всей выбранной области Д/П по диапазонам дат и проверка покрытия |
| `src/nlp/grls_etl.py` | Pydantic-валидация, очистка названий, дедупликация и запись Parquet |

Основной справочник включает только Д («Действующий») и П («Действует, на подтверждении государственной регистрации»). Другие состояния не подмешиваются. Базовый загрузчик не задаёт фильтр автоматически; сборщик Д/П задаёт его явно. Браузерные cookies и токены не используются.

API может возвращать неполные объекты при большой выборке. Полнота подтверждается совпадением уникальных непустых `lpId`, размеров частей и счётчиков API до и после загрузки, с проверкой статусов. `coverage_scope` ограничивает вывод о полноте выбранными состояниями; выгрузка Д/П не означает выгрузку всего реестра.

Исходные HTTP-ответы сохраняются без изменения байтов. Исправление подозрительной кодировки выполняется только опционально в ETL. Несколько кодов МНН/АТХ сохраняются; неподтверждённые попарные связи не создаются. `mnnName="~"` считается отсутствующим значением.

## Данные

| Путь | Содержимое |
|---|---|
| `data/raw/grls/` | Исходные ответы, контрольные запросы и manifest |
| `data/processed/grls_normalized.parquet` | `trade_name_norm`: String, `inn_norm`: String, `atx_code`: List(String) |
| `data/processed/grls_normalized_records.parquet` | Идентификаторы, регистрационные номера, исходные названия, массивы кодов, статусы, формы и происхождение |
| `data/processed/grls_normalized_report.json` | Покрытие источника и статистика исключений |

`--mapped-only` оставляет в поисковой таблице заполненные связи. Непригодные страницы пропускаются с отчётом; на смешанных страницах пригодные записи сохраняются. Некорректный JSON и неизвестная схема блокируют запись результата. Число уникальных связей отличается от числа регистрационных записей из-за дедупликации.

## Правила работы

- Валидировать структурированные сущности через Pydantic v2.
- Не изменять raw и клиническую логику при технических доработках ETL.
- Перед заменой файлов проверять различия и сохранять необходимые резервные копии.
- Работать через отдельные ветки и PR, без прямых коммитов в `main`; использовать Conventional Commits.
- Секреты настраивать локально. Не включать их значения, личные пути и сертификаты в код или документацию.
- `.env`, виртуальные окружения, raw, Parquet, локальные отчёты и резервные копии исключаются из Git.

## Проверки и дальнейшая работа

Тесты в `tests/` проверяют пагинацию, ошибки HTTP/JSON, покрытие Д/П, сохранность raw, кодировку, множественные коды и воспроизводимость ETL. HTTP в основных тестах мокированный; это не независимая проверка медицинской корректности связей.

Далее: сопоставление лекарственных названий со справочником, извлечение связей из клинических рекомендаций и подключение графа. Команды установки, загрузки, нормализации и тестирования — в [README.md](README.md).
